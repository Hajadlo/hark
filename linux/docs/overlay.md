# Recording overlay verification

Implementation is in `src/overlay.rs`: one Wayland connection/thread, layer-shell
overlay surface, empty input region, no seat binding and keyboard interactivity
none. The 200×44 logical px pill has 12 px shadow padding and its bottom is
32 logical px above the panel. Exclusive zone is 0. Rendering uses bounded shm
buffers, tiny-skia and a fontconfig-selected sans font rasterized by fontdue.
KDE output order selects the main connector; a connected config override wins,
with order/compositor fallbacks if it is missing. Output events re-evaluate the
choice. Ceiling integer buffer scaling keeps fractional outputs crisp.

The capture callback publishes smoothed mono RMS through an atomic. Animation
is capped at about 30 fps while visible. Hidden state destroys the surface and
blocks on channel/Wayland events without a timer. The daemon sends recording,
toggle, processing, success, silence and failure transitions; processing remains
until insertion has finished. Overlay errors only log and disconnect the UI.

New config keys: `overlay = true` (default), optional `overlay_output = "DP-4"`.
The example and README document both.

Tests cover callback-duration-aware smoothing, bounded pulse mapping, output
order/override/missing output/hot-plug choice, fade and message timing, repeated
errors, new recording interrupting a message/fade, font fallback and fractional
offscreen rendering. Physical monitor hot-plug/laptop lid and visual inspection
on the real screen remain acceptance checks; no screen screenshot was taken.

PNGs live at `<worktree>/.scratch/overlay/`, generated by the release binary's
`overlay-previews` command through the same drawing code. Names are the product
of these sets: state (`recording-low`, `recording-medium`, `recording-high`,
`toggle`, `processing`, `nothing-heard`, `failed`), scale (`1.0`, `1.25`), and
background (`light`, `dark`), formatted as `<state>-<scale>-<background>.png`.
The scratch manifest lists all 28 names. These are synthetic offscreen renders.

## Session evidence

Test daemon used a separate `cz.hajadlo.hark.Test` component, only the confirmed
Ctrl+Alt+Shift+F10 chord, its own config, device `test`, `insert=print`, private
gateway on 8767 and a verified synthetic PipeWire source. Raw/clean one-shot
uploads and toggle capture printed the expected espeak sentence.

The full harness was attempted twice first. Both created and mapped the overlay
on DP-4 and showed processing/done/unmap, but the hold was released prematurely,
truncating the synthetic clip and failing its transcript assertion. During these
tests the installed daemon was auto-restarting because Handy was running. The
first premature release arrived 28 ms after its “quit Handy before binding”
exit, consistent with removal of that process's virtual keyboard resetting the
compositor's shortcut state. Neither installed application was changed or stopped.
The successful run therefore explicitly used `HARK_TEST_TOGGLE_ONLY=1`; a full
hold rerun needs a stable desktop input-device lifecycle.

A second toggle E2E run set an invalid Wayland socket environment for only the
test daemon. It logged one overlay failure, created no surface, and still
captured/uploaded/printed the whole synthetic sentence:

```text
overlay unavailable: Wayland connection: WAYLAND_SOCKET was set but contained garbage; dictation continues
The synthetic dictation test worked correctly
overlay unavailable: dictation still passed
E2E PASS (test token never printed)
```

Both successful runs restored the original clipboard, removed temporary audio
modules and stopped transient units/gateway. Default source before/after was
`alsa_input.usb-046d_HD_Pro_Webcam_C920-02.analog-stereo`; default sink was
`alsa_output.usb-Logitech_Logi_Z407_00000000-01.analog-stereo`.
No paste keystroke was emitted. The installed binary, config and service were
not written or controlled; install this build yourself.
